# Deploying to the Debian LXC

Target: a Debian 13 ("trixie") LXC container, currently `10.11.1.41`, hosting both
`LicensingAdmin` (Blazor Server admin panel) and `LicensingApi` (Web API) side by side.
Both talk to the same remote Postgres instance the Windows dev setup already uses
(`172.16.101.12` / `licensing_app`) — this LXC is web/app tier only, no local database.

## One-time setup (in order)

1. **Provision the box** — from a machine with SSH access to the LXC:
   ```bash
   scp infra/provision.sh root@10.11.1.41:/root/provision.sh
   ssh root@10.11.1.41 "systemd-run --unit=provision --collect \
     --setenv=DEPLOY_PUBKEY='<your deploy SSH public key>' \
     bash -c 'bash /root/provision.sh > /root/provision.log 2>&1'"
   ssh root@10.11.1.41 "journalctl -u provision.service --no-pager"
   ```
   This installs nginx, the .NET 8 ASP.NET Core runtime (via Microsoft's
   `dotnet-install.sh`, not apt — trixie's own .NET packaging is too new to rely on),
   `postgresql-client`, creates a `deploy` user, the `/var/www/licensing/{admin,api}`
   and `/etc/licensing-{admin,api}` directories, and two nginx reverse-proxy vhosts
   (admin on `:80`, api on `:8080`, both proxying to loopback-only Kestrel processes
   on `:5000`/`:5001`). ufw is enabled with only SSH + those two ports open.

2. **Install the systemd units** (one-time, or whenever `infra/systemd/*.service` changes):
   ```bash
   scp infra/systemd/licensing-admin.service infra/systemd/licensing-api.service root@10.11.1.41:/etc/systemd/system/
   ssh root@10.11.1.41 "systemctl daemon-reload"
   ```

3. **Write the production secrets** — these are `EnvironmentFile`s the systemd units
   read; they are never generated by any script here and never committed to git.
   SSH in and create them by hand:

   `/etc/licensing-admin/env` (root:deploy, mode 640):
   ```
   ConnectionStrings__LicensingDb=Host=172.16.101.12;Database=licensing_app;Username=licensing;Password=<real password>
   Crypto__RsaPrivateKeyPem=<PEM-encoded RSA private key, single line with \n escapes, or use a multi-line heredoc — see CryptoRegistration.cs>
   Admin__BootstrapEmail=
   Admin__BootstrapPassword=
   ```
   Leave the two `Admin__Bootstrap*` lines blank once the real SuperAdmin exists in
   `admin_users` (it does — see `team/inbox-arq.md`, 2026-09-13 `[MANUAL]` entry) —
   the seeder is a no-op whenever the table already has rows, but there's no reason to
   carry bootstrap credentials in a production env file once they've served their purpose.

   `/etc/licensing-api/env` (root:deploy, mode 640) — same `ConnectionStrings__LicensingDb`
   and `Crypto__RsaPrivateKeyPem` lines (the API needs the same signing key to verify/
   issue keys consistently with the admin panel).

   ```bash
   ssh root@10.11.1.41
   $EDITOR /etc/licensing-admin/env /etc/licensing-api/env
   chown root:deploy /etc/licensing-admin/env /etc/licensing-api/env
   chmod 640 /etc/licensing-admin/env /etc/licensing-api/env
   ```

   **`Crypto__RsaPrivateKeyPem` is not optional in production.** Leaving it unset
   makes `CryptoRegistration` fall back to an ephemeral in-memory RSA key that is
   regenerated on every restart — every previously-issued license key's signature
   would stop validating the moment the service restarts. Generate a real key pair
   once and keep the private key only in these two `EnvironmentFile`s.

4. **Enable + start the services**:
   ```bash
   ssh root@10.11.1.41 "systemctl enable --now licensing-admin licensing-api"
   ```

## Ongoing deploys

From the build machine (Windows dev box, this repo checkout):
```bash
LXC_HOST=10.11.1.41 ./infra/deploy.sh
```
This publishes both projects framework-dependent for `linux-x64`, rsyncs the output
over (stopping/restarting the services around the sync), and leaves the
`EnvironmentFile`s and systemd unit definitions untouched. Safe to re-run any time.

## Not done yet / open items

- **TLS**: none configured. The LXC is reached by LAN IP with no public DNS name yet.
  Revisit (Let's Encrypt via certbot, or an internal CA) if this becomes
  internet-facing or gets a real hostname.
- **Postgres password**: per `team/inbox-arq.md` (2026-09-13), the current password
  closely resembles the old leaked `Test2020#` and the user has deferred rotating it
  ("proyecto va a correr en local por un tiempo") — not blocking, but the
  `ConnectionStrings__LicensingDb` value above should be updated whenever that
  rotation happens.
- **Backups**: `postgresql-client` is installed on the LXC for ad-hoc `pg_dump`/`psql`
  access, but there's no scheduled backup job yet (mirroring miautrix-website's
  `infra/backup.sh` pattern would be the natural next step if wanted).
